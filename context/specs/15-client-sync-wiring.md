## Existing wire contract

- Join remains `socket.timeout(10000).emitWithAck("workspace:join", { projectId, tabId })`. Preserve S13 ack validation, retry, per-binding ownership, leave, and reconnect behavior. S14 serializes join subscription/snapshot with writes.
- Commit is `socket.timeout(8000).emitWithAck("canvas:commit", { projectId, baseVersion, ops })`. Success is exactly the relevant shape `{ ok: true, version }`. No userId, tabId, role, display fields, or new protocol fields are sent.
- Remote event is `canvas:ops` with `{ projectId, version, ops, by }`. `by` is an authenticated Mongo userId; other tabs of the same user receive it. Never ignore an event merely because by equals your user id.
- Recovery read is `socket.timeout(8000).emitWithAck("canvas:sync", { projectId })`. Success is `{ ok: true, canvas: { nodes, edges, version } }`. S14 queues it after earlier commits on that room, including a commit whose client timeout leaves the outcome uncertain.
- A conflict/op-validation rejection may include `canvas`; other failures have only `{ ok: false, message }`. A timeout does not carry a canvas and does not mean the save failed. No HTTP canvas endpoint, polling, automatic commit retry, or new server event.

## State and edit gate

Keep the existing public `canvas`, `rfNodes`, `rfEdges`, project, role, and route status. The canonical `canvas` graph may contain optimistic edits, but its version is the last acknowledged/installed authoritative version, never an edit counter. Keep the last confirmed graph separately inside the binding/coordinator if needed. Distinguish unsent batches, the one submitted commit (with captured base version and ops), join attempts, and recovery requests. Do not overload S13's join `inFlight` field with commit state.

Each connection/join session starts with empty queues and a fresh sync epoch. Queue state belongs to the binding, not another account, route, socket, or later connection id. A small observable sync state (for example `syncStatus: "idle" | "syncing"`) may be added to the workspace store. During recovery keep the existing workspace shell/canvas mounted but read-only; it may show the last confirmed graph while awaiting the replacement. Failed recovery uses the existing route error/access-denied cards. No new visual component, loading banner, stylesheet, or viewport reset.

Content actions must also check live socket/binding ownership at call time. This catches the known sign-out interval where useSessionStore removes listeners before disconnect and route cleanup has not yet run. Role alone is not permission. No edit queueing while disconnected, joining, recovering, failed, disposed, or bound to a replacement socket. Refused actions restore display geometry from canonical state and return false as today. No-op/invalid actions do not emit.

## Dispatch, batching, and commit success

1. Gate the action, then run real shared applyOps against the current optimistic graph. Reject the entire dispatch on validation failure, with the existing error toast and display restore. Use the returned normalized ops, detached from caller-owned inputs, in the queue.
2. Atomically install the optimistic graph/display and append that dispatch as an ordered batch. Keep the confirmed version unchanged. The existing synchronous boolean dispatch contract stays intact.
3. If no commit is active, submit the oldest pending work promptly. Only one logical commit is active per current session. Further dispatches are optimistic and queue behind it; they cannot start a second commit or reuse its base version in parallel.
4. Combine consecutive waiting dispatch batches up to shared MAX_OPS_PER_COMMIT (50). Preserve order and each dispatch's atomic boundary: never send 51+ ops, truncate, reorder, or split a single accepted dispatch across commits. A single dispatch over 50 already fails shared validation and is not a new bulk-edit feature. Example: with a commit active, queued dispatches of 30 and 30 ops become two later commits, not one 60-op request or a split gesture. No debounce timer, coalescing/rewriting op semantics, or queue-size feature is required.
5. baseVersion is the confirmed version when sending, not the version when dispatch first queued. Capture a unique request token, binding/join/sync epoch, socket object and id, project id, submitted ops and base version before emit. Handle synchronous emit errors and promise rejection/timeout.
6. Accept a current success only if it is a record, ok is exactly true, and version is a nonnegative safe integer equal to submitted baseVersion + 1. Malformed/impossible success is an uncertain outcome requiring sync, not permission to advance arbitrarily.
7. Advance the confirmed snapshot by the submitted normalized batch and set its acknowledged version once. Update only the optimistic graph's version while retaining all later queued edits already visible. Do not apply the successful batch a second time to the optimistic graph, overwrite subsequent edits with the sent graph, or bump on dispatch. Release that commit token and pump the next bounded batch against the new base. A stale callback/finally may not clear a newer token or restart an obsolete queue.

If shared application against the confirmed snapshot unexpectedly fails, stop pumping and recover. No best-effort partial acceptance.

## Remote operations

Register one named `canvas:ops` callback with the current binding and remove that exact reference on disposal. It must honor the same connected socket/id, route, join and recovery ownership rules as acks. Ignore a clearly different project id. Do not use removeAllListeners or register a new listener for every render/dispatch.

Validate current-project events before applying: record shape, matching canonical project id, nonnegative safe integer version, an ops array of 1–50, and a 24-hex by userId string. Use shared applyOps for op semantics and returned normalized graph, never mutate raw event objects into the display. Malformed relevant events or failed op application trigger recovery; unrelated-project events cause no toast, sync, or state change. A non-record/unroutable malformed event may be ignored rather than treating arbitrary traffic as a workspace mutation.

- With no local pending/submitted work and no recovery: version equal to current + 1 applies atomically, updates the confirmed graph/version and display, and emits no commit. It never goes through dispatch. A repeated/older valid version at or below confirmed is ignored. A forward gap triggers sync; do not apply it on a guessed graph.
- If a new remote version arrives while local work is submitted or queued, invalidate that optimistic epoch and recover. Do not merge/rebase, echo the event, retry pending edits, or accept the old commit ack afterward. Older/duplicate versions already confirmed can be ignored without dropping work.
- Events arriving during join/recovery cannot be silently lost. Retain a bounded summary of observed versions (a highest-version watermark is enough) for that connection/attempt. If the eventual snapshot is behind a newer observed event, fetch another sync before enabling editing. Alternatively buffer/replay validated contiguous events, with a bounded overflow-to-sync path. Handle malformed relevant events during recovery conservatively by scheduling one coalesced later sync. Clear all such state on connection/binding replacement. This also covers delivery immediately following join ack before its promise continuation installs the snapshot.

## Recovery and failures

All failure paths use one recovery mechanism. On a current rejection, timeout, malformed ack, invalid remote event, gap, or remote/local collision:

1. Stop the pump, discard every unsent batch, invalidate the submitted commit's callbacks and the prior recovery token, and gate editing before any display rebuild that can blur an editor. Do not turn a blur/unmount into a new queued edit. A still-running server save cannot be cancelled; its late ack is obsolete.
2. Restore the last confirmed graph to remove speculative geometry/content while waiting, or immediately install a trustworthy rejection snapshot. A rejection snapshot is usable only if its envelope/arrays/version validate, it belongs to the still-current request, and its version is not behind confirmed state or remote events already observed. Normalize snapshot content with normalizeCanvas; never invent an empty graph for malformed/missing data. Preserve its explicit version.
3. If the rejection carries no usable snapshot, or the outcome is uncertain, issue canvas:sync on the still-connected, successfully joined socket. Do not emit workspace:leave before sync: it would revoke the membership needed for recovery. No buffered emit while disconnected. Timeout always requires the queued sync, even if a locally retained snapshot exists.
4. Coalesce repeated triggers while one sync is outstanding. Invalidate stale callbacks, and use event-watermark/dirty tracking to avoid letting an older sync ack erase a later committed event. When another read is needed, issue it after the current read settles; do not start parallel syncs or a polling/retry loop. One stable valid snapshot at/above the observed version finishes recovery. No commits are pumped during it.
5. On successful recovery install confirmed/canonical/display together, reset pending work, return to ready/idle sync state, and show exactly one `Canvas re-synced` toast for that recovery episode. No success toast before a server snapshot is accepted and no toast from an obsolete episode. Surface an available server error message once as an error toast (separate from the recovery success message); suppress repeated copies within the same episode.
6. `Project not found` on commit/sync clears project/role/content and shows existing notFound state, with best-effort current connected leave cleanup. Do not reveal or retain another project's graph. `You cannot edit this canvas` requires a fresh workspace join through the existing retry/join mechanism to refresh the role; a successful sync alone cannot justify restoring cached editor authority. Drop pending work first. This does not add S27 membership events or role inference from arbitrary messages.
7. Failed/malformed/timed-out sync clears editable state, shows the existing error card, and cleans up only that current connected workspace as S13 does. The existing Try again action performs a new workspace join. Do not stay ready with a stale graph, claim the edit was saved, retry automatically forever, or fail over to local-only editing.

For step 6, a fresh rejoin after edit denial may complete recovery (one Canvas re-synced toast after a valid role/snapshot); ordinary initial joins/reconnects do not produce that toast. Preserve status/error semantics without changing WorkspacePage. All snapshots validate record/array shape and a safe nonnegative integer version before normalizeCanvas. Existing unsafe legacy versions fail closed rather than being rounded into a writable version; no server migration.

## Lifecycle and ownership

Extend S13 ownership, not just project-id checks. Every commit/sync completion and listener must be bound to the active binding, join attempt/session, socket object, captured socket id and recovery epoch. This matters for same-project remounts, retries, reconnects reusing the socket object, and socket replacement before the old disposer runs.

- A disconnect, fresh join/retry, route exit, reset, binding replacement, or sign-out invalidates join/commit/sync callbacks and remote-event tracking and drops unsent work immediately. Reconnect always joins and installs a fresh persisted snapshot. Never replay queued/uncertain edits or let an old finally start a new send.
- Dispose the old binding while it still owns resources, then replace it; remove only its named connect/disconnect/canvas:ops listeners. Later/double old cleanup cannot clear/leave the new binding or remove its listener. Existing session/chat listeners remain untouched.
- Never flush pending edits on route exit, add beforeunload/pagehide saves, create a second socket, or send a commit/sync while disconnected. Already submitted edits may persist; reconnect/reload shows whatever the server actually saved. Unsent edits are discarded, as the architecture specifies.
- S14 invalidates completed-join authority synchronously on new join/leave/disconnect. Do not overlap client commit pumping with a new workspace join on the same connection. A content action between listener removal and route cleanup must refuse because the live socket is disconnected.
